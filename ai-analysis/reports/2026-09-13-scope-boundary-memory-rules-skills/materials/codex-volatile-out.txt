### A. 分界線：V → memory、P → instruction，我同意；但要加 F

我建議正式分類成：

| 類 | 定義 | 正確載體 |
| --- | --- | --- |
| **V — volatile user state** | 使用者目前訂閱哪家、哪個帳號啟用、哪個 quota pool 可用、目前耗盡／恢復、帳號切換 | **memory**，而且是 rolling state |
| **P — policy** | 任務該如何 route、何時 failover、顯式指定優先權、usage limit 後禁止盲重派、review 用哪類 family | **rule/skill** |
| **F — operational fact** | bridge/harness/provider 實際能力與認證機制，例如某 adapter 會剝 `OPENAI_API_KEY`、某 runtime 是否只有 subscription auth face | **repo/code/ref-docs/reference fact**；若外部且不可從 repo 推導，可放 reference memory |

這個第三類很重要。

例如你舉的：

> `計費鐵則＝muse 純訂閱無 API key 面`

它**不是單純 P，也不一定是 V**。如果「Muse runtime 根本沒有 API-key billing path」是產品／runtime contract，那是 **F**；但「user 現在有 Muse 訂閱、這個窗口目前有額度」才是 **V**。

同理：

> bridge 剝 `OPENAI_API_KEY` 防 API-key 計費翻轉

如果這確實由 bridge 實作保證，就是 repo 可驗的 **F**，照 `memory-audit` Q2 原則甚至不應搬進 memory，而應由程式碼／bridge docs 承載，instruction 最多 pointer。

所以我的 boundary 是：

**instruction 不存 user/account snapshot；memory 不吞 stable policy；repo 可驗的 mechanism fact 也不要因為碰到「計費」兩字就扔進 memory。**

這比單純 `額度|訂閱|帳號|計費 → memory` 安全很多。

### C. 制度化：我建議「語義 taxonomy + 窄機械 guard」，不贊成 broad regex gate

我建議三層，但職責不要混：

**第一層，`memory-audit` 誤置表新增正式 taxonomy。** 這才是規範單一源。例如新增：

> V：user/account/runtime 現況進 user-level instruction → global user state 歸 memory；穩定 policy 留 instruction；repo 可推導 mechanism fact 回 repo/ref source。mixed 內容必拆層。

這一層最重要。

**第二層，機械檢查只能當 candidate detector，不能把 `額度|訂閱|帳號|計費|現值` 做 hard forbidden。**

理由就是 A 的 F 類。像：

- 「額度耗盡不得盲重試」是合法 P；
- 「subscription auth 無 API-key path」可能是 F；
- 「目前 Anthropic 未訂閱」才是 V。

regex 不可能只靠詞彙正確判 carrier。

現有 `check_single_source.py` 已有 `forbidden_pattern` infrastructure，但它現在定位是**能機械判定的 single-source contract 殘留**。拿 broad billing vocabulary 塞進去會違反你們自己「hook/check 必須無語義例外」的原則。

所以若要放進 `sync-sources`，我只贊成**migration 後非常窄的 regression guard**，例如抓已退役的具體 snapshot 句型／header，或新增 advisory `candidate_pattern` 類型而不是 critical gate。

**第三層，不放 `corrections-weekly` 當主掃描。** 它目前職責是挖 user correction、CR 使用、memory telemetry；把 source-carrier lint 塞進去會讓週報變垃圾桶。它可以在再次出現「你又把我的額度寫進 rules」這類 correction 時提供治理證據，但不負責檔案 correctness。

所以我的組合是：

**memory-audit taxonomy = normative；instruction/source audit = semantic candidate scan；sync-sources 只守能機械證明的窄 invariant；corrections-weekly 不加常規掃描。**
