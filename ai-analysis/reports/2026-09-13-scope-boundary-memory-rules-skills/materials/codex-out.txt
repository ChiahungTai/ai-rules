## B. 五個設計問題

| 問題 | 我的推薦 | 最強反方論證 | 裁決 |
| --- | --- | --- | --- |
| 1\. 骨架化到什麼程度 | **minimal semantic closure＋pointer**。不是統一「一行」。 | 每支 rule 一行可把 bundle 壓到最小；skill 又可 trigger。 | **不採全一行。** 只有 Bootstrap＋First-action 皆通過才可 pointer-only。`modern-cli-preference` 已很接近理想兩行；`outward-action-consent`、`tool-discipline` 這類不能硬壓成 slogan。 |
| 2\. guide 定位 | **thin but coherent user operating contract**：描述你的工作環境、跨任務 calibration、rule/skill routing。 | pure index 幾乎零重複，而且 authority 更清楚。 | **不做 pure index。** guide 的價值是讓新 session 在任何 task trigger 前知道「這個 user 怎麼工作」；但它不該再當流程手冊。 |
| 3\. 16 rules 是否聚合 | **維持 16 個 authoring units。** | 合併編輯類／驗證類可少 header、少檔案、降低導航成本。 | **目前不合併。** 節省的 bytes 太小，卻會犧牲 `paths:`、rule↔skill pairing、single-source invariant、獨立 re-audit 邊界。只有兩檔真的有同一 trigger、同一 authority 才值得合併。 |
| 4\. guide 唯一入口＋rules 全 pointer | **不採。** guide orchestration，rules 各自保留必要 gate。 | 單一 router 最乾淨，也最省 context。 | 這會把 guide 變第二份 qualification authority，而且 agent 在第一個 consequential action 前可能尚未觸發 skill。AIR-85 應做的是**逐 rule opt-in projection**，不是全域 pointer 化。 |
| 5\. AIR-85 / AIR-86 順序 | **先定 semantic source target；AIR-85 必須在「最終 deployed bundle 驗收」前完成。** | AIR-85 先做，先知道真實 deployment shape，再改內容較直觀。 | 兩層拆開最好：AIR-86 現在就能定「每檔應留下什麼」；`instruction-writing` / `llm-output` 的 non-CC pointer-only 驗收則等 AIR-85。不要讓 deployment mechanism 反過來決定知識應不應常駐。 |

其中第五點我認為很關鍵：**AIR-86 的 semantic acceptance 不需要等 AIR-85，但 AIR-86 若要宣稱「user-level bundle 最終形態已完成」，就必須等 AIR-85 projection 也被驗收。**

## D. `structure.md` 的 9 對 reference-layering 要不要修

**要修描述，但目前不要增加第 10 對。**

現在的 9 對表在 structure.md:38-50 基本正確。AIR-86 定稿後，我會讓它明確反映三種成熟度：

| symbol-query-routing → symbol-query-routing | 明確標「startup gate＋fallback/no-zero-hit 在 rule；速查／陷阱 body 在 skill」 |

| model-routing → model-routing | 強化成正式 bootstrap split：role→tier/routing vocabulary 在 rule，provider lookup/transport mechanics 在 skill |

我**現在不會加入 `python-standards → python-type-gap`**。`python-type-gap` 只覆蓋第三方 typing gap，並不是 `python-standards` 正文的深層 carrier。若 AIR-86/AIR-85 後真的要讓 Python rule 進 conditional projection，先建立可承接完整正文的 paired carrier，再跑 Bootstrap test；成立後 structure 才加第 10 對。
