其中兩條我是刻意寫得比 writer 版更有鑑別力。

第一，`test_pointer_projection_is_exact_author_line_only` 依 `ep.md:52` 的「section header＋pointer 行 only」把 projected section 限成 **作者 pointer 一行**。我背景讀到目前並行實作在 `scripts/deploy_agents.py:451-473` 多生了一句 `POINTER_ANNOTATION`；若這個 oracle 紅，我傾向先判 **實作超出 frozen contract**。若主 session 認為 deploy-generated annotation 本來就被允許，應修改 EP 明說，不能把測試放寬後假裝沒有規格差異。

第二，`test_second_identical_deploy...` 是 EP `:78` 明載的「deploy 冪等零寫入」強版判準；只驗第二次內容相同不夠。目前背景參考的 `deploy_all()` 是 stage→`os.replace` 每次都走（`scripts/deploy_agents.py:545-586`），因此這條也很可能先紅。這正是 independent oracle 應該抓的差異。

## B. 段 3 行為層測試劇本

### B1. ZCode headless：pointer → Skill first 行為

這個測試我會分成兩個觀察面：

- **Skill 真載入**：ZCode `PreToolUse` user hook 記到 `tool_name=Skill` 且 `tool_input` 指 `instruction-writing`。ZCode hook 的 user-level config、session snapshot 與 PreToolUse stdin contract 分別有本地鏡像證據：`ref-docs/harness/zcode/cn/docs/hooks.md:53-60,61-84,150-173`。
- **Skill body 真進 context**：isolated skill copy 在 body 放一個只存在 body、不出現在 prompt/bundle/description 的 canary；response 必須出現它。只說「instruction-writing」算 description recall，不算 behavior。
- **Premature action**：取 hook log 中第一個 `Skill(instruction-writing)` 前的 PreToolUse；除了 task bookkeeping 類工具外有實質 tool call 就 FAIL。這直接對應研究 `superpowers-testing-research.md:13-16`。

ZCode headless verified argv 是 `node zcode.cjs --mode plan --json --cwd ... --prompt ...`，而且 `--prompt` 必須最後；來源 `/Users/ctai/Github/delegate-bridge/00-tasks/09-10-codex-caller-glm-runtime/poc/zcode-headless-FACTS.md:8-20,97-115`。

有一點我刻意 fail-closed：**測試 home 只提供 `~/.agents/skills`，不偷偷補 `~/.zcode/skills`**。因為 AIR-85 已把 runtime contract 凍結為 `~/.agents/skills`（`ep.md:53-57,111`）。若 headless ZCode 實際只吃 `.zcode/skills`，那是 Q3 runtime-reachability 契約需回主 session 重判，不應由測試偷偷補第二根讓它綠。repo 自己目前聲稱 ZCode 同掃兩根（`skills/CLAUDE.md:15-19`），而鏡像官方 ZCode 文件只明列 `~/.zcode/skills`（`ref-docs/harness/zcode/cn/docs/skill.md:45-62`），所以這個 probe 本身很有價值。

classify() {
  local run_dir="$1"

  uv run python - "$run_dir/pretool.jsonl" "$run_dir/result.json" <<'PY'
import json
from pathlib import Path
import sys

hook_path = Path(sys.argv[1])
result_path = Path(sys.argv[2])

planning_tools = {
    "TodoWrite",
    "TaskCreate",
    "TaskUpdate",
    "TaskList",
    "TaskGet",
}

events = []
if hook_path.exists():
    for raw in hook_path.read_text(encoding="utf-8", errors="replace").splitlines():
        raw = raw.strip()
        if not raw:
            continue
        try:
            events.append(json.loads(raw))
        except json.JSONDecodeError:
            pass

try:
    result = json.loads(result_path.read_text(encoding="utf-8"))
except Exception:
    print("STATE=INCONCLUSIVE reason=unparseable-result")
    raise SystemExit(0)

response = result.get("response")
if not isinstance(response, str):
    print("STATE=INCONCLUSIVE reason=no-response")
    raise SystemExit(0)

skill_index = None
wrong_skill_seen = False

for i, event in enumerate(events):
    tool_name = event.get("tool_name") or event.get("toolName")
    tool_input = event.get("tool_input") or event.get("toolInput") or {}

    if tool_name == "Skill":
        encoded = json.dumps(tool_input, ensure_ascii=False)
        if "instruction-writing" in encoded and skill_index is None:
            skill_index = i
        else:
            wrong_skill_seen = True

premature = []
if skill_index is not None:
    for event in events[:skill_index]:
        tool_name = event.get("tool_name") or event.get("toolName")
        if tool_name and tool_name not in planning_tools:
            premature.append(tool_name)

body_canary = "AIR85_SKILL_BODY_LOADED" in response
recall_only = (
    "instruction-writing" in response.lower()
    and not body_canary
    and skill_index is None
)

if skill_index is not None and body_canary and not premature:
    state = "PASS"
    reason = "skill-first-and-body-loaded"
elif skill_index is not None and premature:
    state = "FAIL"
    reason = "premature-substantive-tool-before-skill:" + ",".join(premature)
elif skill_index is None and body_canary:
    state = "UNEXPECTED"
    reason = "body-canary-without-observed-skill-tool"
elif skill_index is None and response:
    state = "FAIL"
    reason = "instruction-writing-skill-not-observed"
elif wrong_skill_seen:
    state = "UNEXPECTED"
    reason = "only-wrong-skill-observed"
else:
    state = "INCONCLUSIVE"
    reason = "insufficient-observable-evidence"

print(
    f"STATE={state} reason={reason} "
    f"body_canary={str(body_canary).lower()} "
    f"recall_only={str(recall_only).lower()}"
)
PY
}

四態定義：

- `PASS`：Skill hook 在場＋body canary 在場＋其前沒有 substantive tool。
- `FAIL`：沒載 skill，或 Skill 前已有 substantive tool。
- `UNEXPECTED`：例如 body canary 出現但沒有 Skill hook、只調錯 skill、observable ordering 自相矛盾。
- `INCONCLUSIVE`：auth/provider/runtime/output 不可解析，沒有足夠行為證據。CLI exit code 本身不作 behavior verdict，符合 `.agent-tmp/air85/superpowers-testing-research.md:18-20`。

### B2. CC S6：unknown projection keys × `paths:` runtime probe

這裡的權威判準是 `InstructionsLoaded` hook，不是 model 說「我看到 rule」。CC 官方鏡像明列 `InstructionsLoaded` 在 lazy path load 會觸發，且提供 `file_path/load_reason/globs/trigger_file_path`：`ref-docs/harness/claude-code/docs/en/hooks.md:1261-1294`。

我建議三臂，雖然 S6 最少只要 treatment/control：

- **TREATMENT**：有 `paths:`＋三 projection keys，Read matching file → `path_glob_match`。
- **CONTROL**：只有 `paths:`，無 unknown projection keys，Read matching file → 同樣 `path_glob_match`。
- **NONMATCH**：Read 不匹配 file → treatment rule 不應有 `path_glob_match` event。
