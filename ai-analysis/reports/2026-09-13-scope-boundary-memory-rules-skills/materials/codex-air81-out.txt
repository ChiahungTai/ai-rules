## B. 欄位 schema

我不建議把「命令、skill、rule、狀態」各拆一欄，會把 source table 變成索引牆。`workflow.md` 現有三欄後面加一個 **「怎麼做」** 就夠，cell 固定只有三種資訊：

**入口**：這站人或 agent 實際從什麼 command/skill 進去。  
**詳讀**：1–3 個真正的 method/rule authority link。  
**過渡**：只有 target 尚未落地時才出現，明寫 `❌ target` 與 `現行`。

治理 rule 不需要每站硬塞一個；只有它真的決定該站行為時才放進「詳讀」。否則會把 human navigation 變成 instruction dependency graph。

③④尤其要用這個寫法：

> `❌ target: wt-open / persistent WT 尚未落地；現行：依 repo AGENTS.md「git 慣例」＋ kanban-board 起手式。`

不能把 `wt-open` 做成正常 command link，否則 viewport 看起來會像已可執行。這和 workflow.md 現在明寫 target/runtime 分離是一致的。

## C. `index.html`：我選「保留總覽表＋八張 compact guide cards」

## E. 執行拆分

**同意：先做 `workflow.md` source＋AIR-81 卡 scope，`index.html` 留 AIR-81 實作弧。**

這個拆分是乾淨的，因為 source/projection ownership 已經分開。唯一條件是 source 一旦先行，必須讓卡明確記錄「index projection 暫時 stale、由 AIR-81 收斂」，不能讓它變成無 owner 的 drift。

也就是：

`workflow.md source 定稿 → AIR-81 明列 pending projection → AIR-81 刷 index.html`

而不是要求 source 與 human viewport 永遠原子提交。後者會讓「先把資訊架構定對」與「HTML rendering」不必要地綁死。
