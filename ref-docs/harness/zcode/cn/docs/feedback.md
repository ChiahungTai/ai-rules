用户反馈与支持
为帮助技术团队更高效地定位并排查您遇到的问题，建议在反馈时提供详细的使用场景、操作路径以及相关的报错日志。您可以通过以下任意一种方式向我们反馈：
用户反馈表（飞书）：填写 用户反馈表，适合一次性提交完整问题信息。
应用内反馈：从右上角统一反馈入口或报错提示进入，详见下方 应用内反馈入口。
GitHub Issues：前往 zai-org/feedback 提交 Issue，适合需要追踪进展、与团队公开讨论的问题。
加入社群：扫码加入飞书或微信用户社群直接联系我们，优先推荐飞书社群，详见下方 加入社群。
应用内反馈入口
ZCode 内置了统一的反馈体系。无论是主动提交建议，还是遇到报错时快速上报，都可以在应用内直接完成。
统一反馈入口
点击右上角的反馈入口，即可展开统一菜单，常用的反馈与支持能力都收拢在这里：
问题上报：打开「提交反馈」面板，提交 Bug、异常表现等问题，支持附带截图与日志。
给产品提需求：希望支持的新能力或体验优化，通过这里直达产品团队。
用户社群：快速获取飞书 / 微信社群入口，加入后可直接与官方团队交流。
产品文档：跳转到当前文档站，随时查阅使用说明。
导出日志：手动导出本地日志压缩包，用于反馈表或 Issue 附件。
报错提示入口
如果界面出现错误提示，可以直接点击提示条右侧的 反馈问题。这种入口会自动带入报错摘要、现场截图和当前会话信息，适合反馈初始化失败、运行时报错等问题。
填写并提交反馈
进入「提交反馈」面板后，按引导补全以下字段即可提交：
问题描述：说明遇到的问题与复现步骤，描述越具体，定位越快。
截图：支持粘贴、拖拽或选择文件，最多可附 5 张；从报错入口进入时会自动带上现场截图。
联系方式：留下邮箱等联系方式，便于我们在需要更多信息时与你联系。
日志：点击 上传诊断日志 后，底部的日志上传选项会默认开启，也可以随时手动关闭。上传的日志我们已做 脱敏处理，会尽量保障你的隐私安全。
我的反馈：处理状态与工单 ID
在「提交反馈」面板左下角点击 我的反馈，可以查看每条反馈的处理进度：状态分为 已提交、开发中、已解决 三种，每条反馈都会生成一个全局唯一的 工单 ID（形如 fb-20260712-9f21），点击右侧图标即可复制。
工单 ID 是该条反馈在反馈平台中的唯一索引，关联着你提交的问题描述、截图、诊断日志与环境信息。在社群沟通或跟进问题进展时，请附上对应的工单 ID：开发同学可以凭此直接检索到完整的反馈上下文，省去重复描述与信息收集环节，显著缩短问题的定位、复现与修复周期。
GitHub Issue 提交格式
为方便我们快速复现和定位问题，建议在 zai-org/feedback 提交 Issue 时按以下格式描述：
标题：一句话概括问题，例如「macOS 上启动后白屏」「Bot @ 触发任务无响应」。
使用环境：操作系统及版本、ZCode 版本、所接入的模型通道（如 Z.ai 或企业模型通道）。
复现步骤：分步骤说明如何稳定触发该问题，便于团队按相同路径复现。
期望表现 vs 实际表现：分别描述您期望发生的结果和实际看到的现象。
日志与截图：参照下方 如何打包日志 附上日志压缩包；如有截图、录屏请一并上传。
若您不确定属于 Bug 还是使用问题，也欢迎直接提交，团队会协助分类与处理。
如何打包日志？
推荐优先使用 ZCode 软件内置的 导出日志 功能；如果导出失败，再按下方说明手动定位日志目录。
macOS 系统
点击右上角统一反馈入口，展开反馈菜单。
点击 导出日志，按提示保存生成的日志压缩包。
将压缩包上传至反馈表中。
如果导出失败，可在 Finder 中选择 前往 -> 前往文件夹...，输入 ~/.zcode 后手动压缩 logs 文件夹。
Windows 系统
点击右上角统一反馈入口，展开反馈菜单。
点击 导出日志，按提示保存生成的日志压缩包。
将压缩包上传至反馈表中。
如果导出失败，可打开 文件资源管理器，在地址栏输入 %USERPROFILE%\\.zcode 并回车。
进入目录后，选中 logs 文件夹，右键选择 发送到 -> 压缩(zipped)文件夹。
