# 深層思考框架

> **載入機制**: 本檔 source 在 ai-rules repo `rules/`；各家 harness 經全域 guide 部署載入（Claude 端另有 `~/.claude/rules/` symlink auto-load）

---

## 核心原則

**所有決策必須經過兩層思考：第一性原理（向下分解，找到本質）+ 第二層思考（向前追蹤，預見後果）。**

只做第一性原理分析，會產生「本質正確但後果災難」的決策（如 Tesla 生產地獄：製程設計從物理原理出發完全正確，但未追蹤過度自動化在真實工廠環境的連鎖後果）。

---

## 思維框架

```
第一性原理（向下分解）                  第二層思考（向前追蹤）

1. 追溯基本問題 → 本質需求是什麼？不可妥協的約束？
2. 拆解到基本元素 → 基本組件與本質職責
3. 從基本原理重構 → 最佳方案？本質權衡？
4. 驗證假設 → 查證事實，根據證據調整
                                  ↓
5. 追蹤連鎖後果 → 「接下來會怎樣？」至少追蹤兩層（強制）
6. 評估完整影響 → 負面後果可接受嗎？需要重新分解嗎？
                                  │
                       後果不可接受 → 回到步驟 1 ─┘
```

**步驟 5-6 是強制的**，所有決策都必須追蹤至少兩層後果。判斷需要更深入分析的信號：決策影響多個模組/系統、修改公開 API 或跨專案方法論、第一層後果出現不確定性（「可能」「或許」）、歷史上同類決策曾出錯。

## 決策分級

| 決策類型 | 思考深度 | 判斷標準 |
|---------|---------|---------|
| **單向門**（不可逆） | 第一性原理 + 多層後果追蹤 | 錯了無法逆轉：DB migration、公開 API 合約、跨專案方法論、生產架構 |
| **雙向門**（可逆） | 第一性原理 + 第二層後果追蹤 | 錯了可以回退：內部重構、開發工具、配置調整 |

---

## 關鍵問題

**第一性原理層（本質是什麼？）**——0. **讀者是誰**（這份文檔/UC/架構的讀者是誰？帶著什麼問題來讀？讀完應該能做什麼決策？必須在任何分析之前先回答）；1. **本質需求**（必須做到什麼？不可妥協的約束？）；2. **為什麼需要**（解決什麼本質問題？沒有它會怎樣？）；3. **權衡**（每個選擇用什麼換取什麼？）；4. **驗證**（什麼事實會推翻這個設計？）。

**第二層思考（接下來會怎樣？）**——5. **第一層後果**（直接影響）；6. **第二層後果**（第一層影響又導致什麼）；7. **如果我是錯的**（最壞情況？可以逆轉嗎？逆轉成本？）。

## 程式碼查證與連鎖後果

- **查證**：專案程式碼直接讀取源碼；套件源碼從 `.venv/lib/python*/site-packages/` 讀取確認實際行為；用具體路徑（如 `.venv/lib/.../main.py:122`），不憑記憶
- **連鎖後果追蹤**：修改 A 模組 → 依賴 A 的 B/C/D 受影響嗎？→ B 的下游消費者受影響嗎？新增抽象層 → 減少什麼複雜度？引入什麼認知負擔？改名/重構 → 所有引用處更新？文檔同步？下游斷裂？

## 觸發情境

架構變更、技術選型、設計決策、性能優化、重構建議、股票分析（→ 載入 `trading-analysis` skill）、AI 建議評估、文檔架構決策（instruction 檔結構重組、章節劃分）、資訊架構決策（怎麼組織資訊讓讀者最快找到需要的東西）。

## 輸出格式

```markdown
## 深層思考分析

**本質需求**: [必須做到什麼？不可妥協的約束？]

**基本元素拆解**: [基本組件與本質職責]

**從基本原理推導**: [最佳結構？本質權衡？]

**驗證**: [如何驗證？什麼事實會推翻？引用來源：路徑:行號]

**連鎖後果追蹤**:
- 第一層後果：[直接影響]
- 第二層後果：[連鎖效應]
- 負面情境：[如果錯了會怎樣？]

**決策類型**: 單向門 / 雙向門
```
